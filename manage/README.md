# Mail 管理中心 — 部署说明（给 aa，Serv00 + SnappyMail）

这是一个 PHP 小程序（`index.php` + `imap.php` + `oauth.php` + `ms_oauth.php` + `henna.php` + `cloudmail.php` + `adapters.php`，无数据库、无 Composer），
让你**只登一个页面**就能管所有邮箱、读信发信：
左边栏目都在同一个页面里——收件箱 / 写信 / 邮箱管理 / 添加邮箱 / 设置，
不用再分 `?admin` 和主站两个网址来回跳。

**v2 起它就是一个完整的收发信客户端，不再需要 SnappyMail 来读信发信。**
收件箱、读信、回复、转发、写信、删除、标记垃圾邮件都在本站完成，
SnappyMail 只留作备用入口，见设置页最下方的说明。

## 1. 先准备（不用再建 ~/manage-data）

Serv00 的 PHP 有 open_basedir 限制，只允许访问网站目录，
`~/manage-data` 这种网站外的目录 PHP 读不到，会在页面顶部报一堆警告。
所以新版把数据改存在 `manage/data/` 里（程序第一次打开时自动建），
数据文件存成 `.php`、开头加 exit 保护，直接从网址打开也看不到内容，
凭据本身也是加密存的。旧的 `~/manage-data` 不用建了，
已经建了的也不用管，可以删掉：`rm -rf ~/manage-data`。

## 2. 上传文件

把 `manage/` 里的文件传到 Serv00。两种放法都可以（任选一种）：

- **A. 放在 SnappyMail 旁边（子目录）**：传到
  `~/domains/mail.lele.pp.ua/public_html/manage/`，
  打开 `https://mail.lele.pp.ua/manage/`。
- **B. 单独一个子域名（aa 已选这种）**：传到新网站的根目录，如
  `~/domains/mangguo.lele.pp.ua/public_html/`，
  打开 `https://mangguo.lele.pp.ua/`，后面不用加文件夹名。

传完后应该是这样（以 B 为例）：

```
mangguo.lele.pp.ua/public_html/
  index.php            ← 本次的管理中心（主程序）
  imap.php             ← 收发信库（IMAP / SMTP / MIME 解析，必须和 index.php 放一起）
  oauth.php            ← 微软 OAuth2 入口（Outlook / Hotmail 登录用，和 index.php 放一起）
  ms_oauth.php         ← 微软 OAuth2 共用函数（令牌换取 / 刷新 / XOAUTH2，和 index.php 放一起）
  henna.php            ← Henna 域名邮箱接入（走 Henna 的 HTTP API，没有 IMAP/SMTP，和 index.php 放一起）
  cloudmail.php        ← Cloud Mail 域名邮箱接入（走 Cloud Mail 的 HTTP API，和 index.php 放一起）
  adapters.php         ← 域名邮箱适配器注册表（v4.30，index.php 靠它认 Henna / Cloud Mail，和 index.php 放一起）
  adapter-template.php ← 给别人抄的适配器模板，不用传上服务器
  README.md            ← 本文件
  CHANGELOG.md         ← 版本记录
  data/                ← 程序自动建，别删
```

注意：`imap.php`、`oauth.php`、`ms_oauth.php` 必须和 `index.php` 在同一个目录，缺了收件箱打不开、Outlook 加不上。

数据存在 `manage/data/` 里（site.php、mailboxes.php、salt.php），
由程序自动建，不用手动建。别删这个 data 文件夹，删了邮箱记录就没了。

## 3. 第一次打开，设登录账号和站点密码

登录是账号 + 站点密码（账号默认 admin，第一次打开时可以改，之后在设置里改）。登录页勾上「记住我」，按选的时长不用再登录：3 个月、6 个月、1 年三档，默认 3 个月，每次打开顺延，只在这台设备 / 浏览器上记住；设置里可以改默认时长。点「退出」会把这台设备的记住也清掉。改站点密码后，所有记住的设备都要重新登录。

浏览器打开：

```
https://mail.lele.pp.ua/manage/
```

第一次会让你设一个**登录账号**和**站点密码**（密码至少 8 位）：
- 账号默认是 admin，可以改成你自己的；密码是进管理中心用的，别用 QQ 密码、别用邮箱登录密码，
  也别用 SnappyMail 管理员密码，单独设一个，记好。
- 设好以后，每次打开这个页面输账号 + 密码；勾上「记住我」就 30 天不用再输。

> 记好它：站点密码忘了，存着的邮箱凭据就解不开了，
> 只能把邮箱逐个删除、重新添加。

## 4. 加 QQ 邮箱（用授权码，最稳）

1. 先去 QQ 邮箱：`mail.qq.com` → 设置 → 账户 →
   把 **IMAP/SMTP 服务** 开启，按手机验证生成一个**授权码**（16 位字母）。
2. 回管理中心 → 左边 **添加邮箱**：
   - 邮箱地址：填完整地址，如 `xxx@qq.com`
   - 登录方式：选 **授权码 · 应用专用密码**
   - 密码 / 授权码：粘贴刚才那个授权码（别手打，别带空格）
   - 服务器会自动填好：IMAP `imap.qq.com:993` SSL，SMTP `smtp.qq.com:587`
3. 先点 **测试连接**，通过了再点 **保存邮箱**。

## 5. 加 Outlook 邮箱（微软账号登录，v4.0）

微软自 2024-09-16 起个人 Outlook / Hotmail 只认微软账号登录（OAuth2），
密码和应用专用密码都登不上。所以 Outlook 不再走密码方式，改成这样（只做一次）：

**第一步：去 Azure 注册一个应用（在你自己的微软账号里做）**

1. 打开 https://portal.azure.com → 左边「应用注册」→「新注册」。
2. 名称随便填一个，比如 `芒果邮箱管理中心`。
3. 帐户类型选「任何组织目录中的帐户和个人 Microsoft 帐户」。
4. 平台选 **Web**，重定向 URI 填（管理中心设置页也有这个，一字不差）：
   `https://mangguo.lele.pp.ua/oauth.php?step=ms_callback`
5. 点「注册」，注册完在概览页记下「应用程序（客户端）ID」。
6. 左边「证书和密码」→「新客户端密码」→ 说明随便填、有效期选最长的 →
   点「添加」后把「值」那一栏复制下来——**只显示这一次**，关掉页面就再也看不到了。
7. 左边「API 权限」→「添加权限」→「Office 365 Exchange Online」→
   「委托的权限」→ 勾选 `IMAP.AccessAsUser.All` 和 `SMTP.Send` →「添加权限」。
   个人账号不需要管理员同意，做完直接能用。

**第二步：把 Client ID 和 Secret 填进管理中心**

管理中心 → 设置 →「微软账号登录（Outlook / Hotmail）」卡片：
- Client ID：粘贴第 5 步的应用程序（客户端）ID
- Client Secret：粘贴第 6 步复制的那个值
- 点「保存微软登录信息」。Secret 是加密存的，页面上不会明文显示。

**第三步：用微软账号登录添加**

添加邮箱 → 不用填密码和服务器，直接点绿框里的「用微软账号登录添加」→
跳到微软登录页，输 Outlook 邮箱和正常密码登一次 → 同意授权 →
自动跳回管理中心，邮箱就加上了，列表里带「微软登录」标记。

- 令牌过期自动刷新：access token 快过期时，打开收件箱或发信时
  自动用 refresh token 换新的，不用重新登录；refresh token 长期有效，
  除非在微软账号里撤销了应用授权。
- 令牌拿不到了（比如撤销了授权）：删掉这个邮箱，重新点「用微软账号登录添加」。
- QQ / Gmail 不受影响：QQ 还是授权码，Gmail 还是应用专用密码，见第 4 节和第 7 节。

Gmail 还是应用专用密码（IMAP `imap.gmail.com:993`，SMTP `smtp.gmail.com:587`），
163 填 `imap.163.com:993` / `smtp.163.com:465`。

## 6. 平时怎么用

- 打开管理中心（`https://mangguo.lele.pp.ua/` 或 `https://mail.lele.pp.ua/manage/`），输站点密码进中心。
- **收件箱（三栏）**：点左栏「我的邮箱」里某个邮箱就只看它一个（进站默认是第一个邮箱的收件箱）；左栏没有“全部收件箱”入口了（原来点它要把所有邮箱的最新邮件一起取回来，太慢）。分组筛选里的“全部”链接还会打开全部收件箱——所有邮箱的最新邮件合在一起、按时间从新到旧排，一页 30 封。中间是文件夹（收件箱 / 垃圾邮件 / 已发送 / 草稿箱 / 已删除，垃圾邮件紧跟收件箱）和邮件列表：按月份分组（组头是“本月 / 10月 / 9月 …”，本月那组默认展开、其他组点开看），每封是三行——发件人 + 时间、主题（未读加粗、带绿点）、正文摘要（灰色小字）。点一封就在右栏打开读信，同时标为已读。上下页翻 30 封一批。每封邮件右下角直接有个 🗑 删除图标，点一下就移到已删除，不用点开再删。没选邮件时右栏显示“点一封邮件查看”。
- **列表有缓存，进收件箱秒进**：列表（发件人、主题、摘要、时间）默认缓存 1 分钟，1 分钟内再进直接读缓存，不用重新连邮箱；文件夹栏旁边有 **↻ 刷新**，点一下就现场取最新，不受缓存时间限制。缓存时间在设置页改（1–60 分钟）。新邮件最多晚一个缓存周期出现，急着看就点刷新。发信、删信、移到垃圾箱、改登录方式、删邮箱后缓存自动清掉。
- **读信**：右栏显示发件人、收件人、抄送、时间、主题和正文（纯文本；只有网页正文的信会自动转成纯文本显示）。附件只显示文件名和大小，点一下下载，不在线打开。读信页没有删除按钮，删除只在列表里做。
- **回复 / 转发**：读信页点「回复」（收件人自动填原发件人，主题加 Re:，正文带原文）或「转发」（收件人空着，主题加 Fwd:，正文带原文），改好点发送。
- **写信**：左边点「写信」，填收件人（多个用逗号隔开）、抄送（可选）、主题、正文，点发送。发出去的信会尽力在已发送里存一份。
- **删除 / 标记垃圾邮件**：列表里每封右下角点 🗑 就移到已删除；读信页没有删除按钮，点「标记垃圾邮件」移到垃圾邮件。删错了去已删除里找（本中心没有“彻底删除”按钮）。
- **邮箱管理**：看每个邮箱的状态（连接成功 / 连接失败），
  点 **测试连接** 重新测，点 **读信** 直接打开这个邮箱的收件箱。
  想换登录方式（比如从登录密码换成授权码，或反过来），点 **改登录方式**，
  在表单里二选一、填新的密码 / 授权码、保存就行，不用删了重加。
  表格太宽时可以左右拖动看，不会再挤成竖排字。
  每个邮箱都有分组（默认“未分组”）：添加 / 改登录方式时填分组，
  也可以在表格里直接改分组名。拖动表格行可以调换邮箱顺序，
  拖完点 **保存排序**；左栏「我的邮箱」就是按分组和这个顺序排的。
- **添加邮箱**：按第 4、5 节再加，数量不限。
- **设置**：改站点密码、改默认显示名称；SnappyMail 的备用入口在设置页最下方。
- 退出点右上角 **退出**。

## 7. 两种登录方式，到底有什么区别？（实话）

| 方式 | 什么时候能用 |
|---|---|
| 登录密码 | 邮箱没开两步验证、厂商还允许密码直连时。QQ / Gmail / Outlook 开了两步验证后，服务器通常直接拒收，报认证失败（903 / AUTHENTICATIONFAILED）。 |
| 授权码 · 应用专用密码 | QQ 只有这一种能用；Gmail 开了两步验证后也要用这个。第一次填一次，之后存在管理中心里。 |
| 微软账号登录（v4.0） | Outlook / Hotmail 专用：跳到微软登录页登一次，之后用令牌收发信，不用密码、不用应用密码。 |

所以：**QQ 一律选授权码；Gmail 用应用专用密码；Outlook 用微软账号登录（第 5 节）**。
（SnappyMail 管理后台 → 插件，开 `login-gmail` / `login-o365`，
去 Google Cloud / Azure AD 建 OAuth 应用，之后在 Google/Microsoft
自己的页面输正常密码登录——那是 SnappyMail 自己的路子，和本中心无关）。QQ 没有 OAuth，这条对 QQ 无效。

注：本中心的「测试连接」只测 IMAP 的 SSL 993 端口（QQ / Gmail / Outlook 的默认端口都是 993），不测 STARTTLS 143 端口；发信是否正常，写一封发给自己验证最准。

测试失败时先看页面上的提示：
- “服务器拒登 / 密码不对”→ 换成授权码 / 应用专用密码，重新生成一个再试；
- 失败多次后还报同样错误 → 可能是限频，等 10 分钟再试一次，别连着点；
- “连不上服务器”→ 检查 IMAP 服务器地址和端口有没有填错
  （常见错：`qq.comimap.qq.com`，正确是 `imap.qq.com`）。

## 8. v2 收发信的实话与限制

- **v3 修的两个 bug**：收件箱顶部曾冒出一堆英文 `preg_split` 警告，是 `imap.php` 里一个正则字符类没闭合，已经修好；另外程序开头加了 `display_errors` 关闭，以后就算再有警告也不会直接显示在页面顶部。邮箱管理表格也改成横向滚动，不会再挤成竖排字。
- **不用跳去 SnappyMail 了**：读信、回信、转发、写信、删除、标记垃圾邮件都在本站完成。
- **没有新邮件推送**：打开收件箱才去服务器拉最新 30 封，不会自动提醒；想看新邮件就点文件夹栏下面的 **↻ 刷新**。
- **缓存只管列表**：缓存的是邮件列表，读信正文和附件还是每次现场取；读完一封信，已读状态最多晚一个缓存周期才在列表里变过来，点刷新立刻变；第 2 页起没有缓存，每次都现场取。
- **正文是纯文本**：写信只能写纯文本，不支持富文本、加粗、插图；读信时只有网页正文的信会自动转成纯文本显示，样式会丢，只留文字。
- **附件只能下载**：附件不在线打开、不在线预览，点文件名下载到本地再看；写信 v1 不能添加附件。
- **一次只看 30 封**：大邮箱按 30 封一页翻，不是一次全拉下来。
- **QQ / Gmail 还是要授权码 / 应用专用密码**：这是厂商服务器的规则，换成自建收发信也绕不过，见第 7 节。登录密码登不上的邮箱，在本站一样登不上。**Outlook 例外**：v4.0 起改走微软账号登录（第 5 节），不再用应用专用密码。
- **「测试连接」只测收信**：它只试 IMAP 能不能登上，不测发信（SMTP）。测试成功只说明收信没问题，发信还得真的发一封才知道。发信认证先试 AUTH LOGIN，服务器不支持就自动换 AUTH PLAIN（v4.27.9，DNSHE 的 SMTP 就只认 PLAIN）。
- **中文文件夹名（v4.27.10）**：有的中文邮箱（比如 DNSHE）文件夹叫「已发送」「草稿箱」这种中文名，IMAP 传文件夹名要用 modified UTF-7 编码，直接发 UTF-8 服务器不认，会报“打不开文件夹”。这版收下来先解成 UTF-8 再认名字，发的时候再编回 UTF-7；编完还打不开就用原名重试一次。QQ、Outlook 的文件夹是英文名，不受影响。
- **改了服务器要记得点「保存邮箱」**：只点「测试连接」不会保存，改完 SMTP 端口/加密要再点「保存邮箱」，发信用的才是存好的配置。
- **已发送副本尽力存**：发信成功后会往已发送文件夹追加一份，厂商要是没有已发送文件夹或拒绝追加，信本身还是发出去了，只是不存副本。
- **删除是“移到已删除”**：不是彻底删，删错了去已删除文件夹里找。**Henna 例外**：Henna 没有已删除，删除就是彻底删除，见第 10 节。

## 10. Henna 域名邮箱（v4.27）

Henna 面板（https://email.070605.xyz/）没有 IMAP / SMTP 服务器，邮件存在它自己的数据库里，所以不能像 QQ 那样填 imap 服务器直接加。v4.27 起管理中心多了一个 Henna 专用接入：走 Henna 自己的 HTTP API 收发，收件箱、读信、回复、转发、写信、发信、删信都在本站完成，和 QQ 邮箱用起来一样，只是有几处不一样：

- **怎么加**：添加邮箱时厂商选「Henna（域名邮箱）」（厂商栏在表单最上面），蓝框里填三样：Henna 面板地址（默认 https://email.070605.xyz）、Henna 登录账号（登面板用的邮箱）、Henna 登录密码（也可以直接贴面板设置里的 API Key）。登录账号一般和下面「邮箱地址」栏填的域名邮箱一样，会自动填过去，不用重复填；面板账号和邮箱地址不一样就自己改。点「测试连接」，面板上找得到这个邮箱地址才算通过。
- **文件夹对应**：收件箱 → Henna 的 in、已发送 → out、草稿箱 → draft、垃圾箱 → spam。**Henna 没有已删除**：点「已删除」只会看到一句提示，里面是空的；删信（列表里的 🗑、读信页的「彻底删除」）都是彻底删除，删了找不回来，点之前确认框会再问一次。
- **一次只看最新 30 封**：Henna 的列表接口不给总数，这一版每个文件夹只显示最新 30 封，没有下一页；想看更早的去 Henna 面板。
- **发信是纯文本**：和本站写信一样，没有富文本、没有附件；抄送没有单独的抄送栏，抄送的人会并进收件人一起发。
- **读信**：优先显示纯文本，没有纯文本就把网页正文剥成纯文本显示；附件点文件名下载。
- **列表缓存和刷新**：和 IMAP 邮箱一样，列表缓存 1 分钟、点 ↻ 刷新立刻现场取；发信、删信后自动清缓存。
- **TG 新邮件通知**：这一版 Henna 邮箱还不推新邮件通知（轮询走 IMAP，Henna 连不上只会记一条备注，不会报错）。
- **收件箱显示（v4.27.7）**：中文主题在 IMAP 里是按 `{字节数}` 字面量传的，旧版解析器不认，主题会显示成 `{69}` 这种标记——这版修了，中文主题、中文发件人名都正常显示；发件人名字如果只有一个英文字母（Henna 发出的信常写成 `e`），列表和读信页直接显示邮箱地址；正文摘要有的服务器放在引号里返回，这版也认了。写信正文不填也能发（v4.27.7 曾改成必填，aa 说测试信只填主题也要能发，v4.27.8 已撤掉）。
- **没有 Henna 邮箱时**：原来的 IMAP 邮箱一动没动，行为和 v4.26 一模一样。

更新时先备份、再传新文件（回滚命令见 CHANGELOG v4.30 一节）。`henna.php`、`cloudmail.php`、`adapters.php` 必须和 `index.php` 在同一个目录，缺了 `adapters.php` 全站 500、缺了某个适配器文件对应的域名邮箱打不开。
